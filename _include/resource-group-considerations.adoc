리소스 그룹을 생성할 때 다음 시나리오를 고려하십시오:

* 리소스 그룹에 데이터 저장소 또는 네임스페이스를 추가하기 전에 수동 탐색을 시작하거나 예약된 탐색이 실행될 때까지 기다리십시오. 이렇게 하면 VM이 탐색되어 리소스 그룹에 표시됩니다. 수동 탐색을 시작하지 않으면 리소스가 리소스 그룹에 표시되지 않을 수 있습니다.
* 데이터스토어에 하나 이상의 리소스(VM 또는 네임스페이스)가 있는지 확인하십시오. 데이터스토어에 리소스가 없으면 Disaster Recovery가 데이터스토어를 탐색하지 않습니다.
* 단일 데이터 저장소는 두 개 이상의 복제 계획으로 보호되는 VM을 호스팅해서는 안 됩니다.
* 보호된 리소스와 보호되지 않은 리소스를 동일한 데이터스토어에 호스팅하지 마십시오. 보호된 리소스와 보호되지 않은 리소스를 동일한 데이터스토어에 호스팅하면 다음과 같은 문제가 발생할 수 있습니다.
+
** 재해 복구는 SnapMirror를 사용하고 시스템이 전체 ONTAP 볼륨을 복제하기 때문에 해당 볼륨의 사용 용량이 라이선스 계산에 사용됩니다. 이 경우 보호되는 VM과 보호되지 않는 VM 모두에서 사용되는 볼륨 공간이 이 계산에 포함됩니다.
** 리소스 그룹 및 관련 엔티티를 재해 복구 사이트로 페일오버해야 하는 경우, 보호되지 않은 리소스(리소스 그룹에 속하지 않지만 ONTAP 볼륨에 호스팅된 VM 또는 네임스페이스)는 페일오버 프로세스로 인해 소스 사이트에 더 이상 존재하지 않게 되어 소스 사이트에서 보호되지 않은 VM이 실패하게 됩니다. 또한 Disaster Recovery는 페일오버 사이트에서 이러한 보호되지 않은 리소스를 시작하지 않습니다.


* 리소스를 보호하려면 해당 리소스를 리소스 그룹에 포함시켜야 합니다.


*모범 사례*: NetApp Disaster Recovery를 배포하기 전에 VM을 구성하여 데이터스토어 확산을 최소화하십시오. 보호가 필요한 VM은 데이터스토어의 일부에 배치하고, 보호되지 않을 VM은 다른 데이터스토어에 배치하십시오. 특정 데이터스토어에 있는 VM이 서로 다른 복제 계획의 보호를 받지 않도록 하십시오.
