[[select-vm-resources-for-protection]]
== 보호할 VM 리소스를 선택합니다

가상 머신(VM)을 보호하는 방법은 여러 가지가 있습니다. 다음 단계는 vCenter 데이터스토어 전체를 보호하는 방법을 보여주지만, 필요에 가장 적합한 방법을 선택해야 합니다.

* *개별 VM 선택*: *가상 머신* 버튼을 선택하면 보호할 개별 VM을 선택할 수 있습니다. 각 VM을 선택하면 서비스는 해당 VM을 화면 오른쪽에 있는 기본 리소스 그룹에 추가합니다.
* *이전에 생성된 리소스 그룹 선택*: 재해 복구 메뉴의 리소스 그룹 옵션을 사용하여 사용자 지정 리소스 그룹을 미리 생성할 수 있습니다. 복제 계획 생성 중에 다른 두 가지 방법을 사용하여 리소스 그룹을 생성할 수 있으므로 이 옵션은 선택 사항입니다. 자세한 내용은 link:../use/drplan-create.html["복제 계획 만들기"]을 참조하십시오.
* *전체 vCenter 데이터스토어 선택*: 이 옵션을 선택하면 데이터스토어에 있는 모든 VM이 볼륨의 일부로 복제됩니다. 복제 계획으로 보호해야 할 VM이 여러 개인 경우 개별 VM을 선택하는 대신 이 옵션을 사용하십시오. 대부분의 경우 Disaster Recovery를 사용하여 데이터스토어에 있는 모든 VM을 보호하고 재시작해야 합니다. 이 옵션을 사용하면 선택한 데이터스토어에 있는 VM을 보호 대상 VM 목록에 추가하도록 서비스에 지시할 수 있습니다.


.이 페이지에 접근하는 단계
. *복제 계획* 페이지에서 *응용 프로그램* 섹션으로 이동합니다.
. 열리는 *신청* 페이지에서 정보를 검토하세요.
+
image:evs-create-rp-wiz-b-1-4.png["복제 계획, 애플리케이션 페이지"]

. *데이터 저장소*를 선택하세요.
. 보호하려는 각 데이터 저장소 옆에 있는 확인란을 선택하세요.
. 필요에 따라 리소스 그룹 이름 옆에 있는 연필 아이콘을 선택하여 리소스 그룹의 이름을 적절한 이름으로 변경할 수 있습니다.
. *다음*을 선택하세요.




[[map-resources]]
== 리소스 매핑

보호할 VM을 선택한 후에는 네트워크 매핑을 수행해야 합니다. 네트워크 매핑은 네 가지 영역으로 구성됩니다.

* 컴퓨팅 리소스
* 가상 네트워크
* VM 재구성
* 데이터 저장소 매핑


각 VM에는 처음 세 가지 유형의 정보가 필요합니다.  보호할 VM을 호스팅하는 각 데이터스토어에 대해 데이터스토어 매핑이 필요합니다.

* 주의 아이콘(image:evs-caution-icon.png["20.20"])이 있는 섹션에서는 매핑 정보를 제공해야 합니다.
* 확인 아이콘(image:evs-check-icon.png["20.20"])으로 표시된 섹션은 기본 매핑을 사용하거나 이미 매핑되어 있습니다. 현재 구성이 요구 사항을 충족하는지 확인하려면 매핑을 검토하십시오.


.액세스 리소스 매핑
. *복제 계획* 페이지에서 *리소스 매핑* 섹션으로 이동합니다.
. 열리는 *리소스 매핑* 페이지에서 정보를 검토하세요.
+
image:evs-create-rp-wiz-c0.png["복제 계획, 리소스 매핑 페이지 생성"]

. 필요한 각 매핑 카테고리를 열려면 섹션 옆에 있는 아래쪽 화살표(*v*)를 선택하세요.




[[compute-resources-mapping]]
=== 컴퓨팅 리소스 매핑

하나의 사이트에 여러 개의 가상 데이터센터와 여러 개의 vCenter 클러스터가 존재할 수 있으므로, 장애 조치 발생 시 VM을 복구할 vCenter 클러스터를 식별해야 합니다.

.단계
. DR 사이트에 있는 데이터 센터 목록에서 가상 데이터 센터를 선택합니다.
. 선택한 가상 데이터 센터 내의 클러스터 목록에서 데이터스토어와 VM을 호스팅할 클러스터를 선택합니다.
. 선택적으로 대상 클러스터에서 대상 호스트를 선택할 수 있습니다.
+
Disaster Recovery가 vCenter의 클러스터에 처음 추가된 호스트를 선택하기 때문에 이 단계는 필요하지 않습니다. VM은 해당 ESXi 호스트에서 계속 실행되거나, VMware DRS가 구성된 DRS 규칙에 따라 다른 ESXi 호스트로 이동합니다.

. 선택적으로 VM 등록을 저장할 최상위 vCenter 폴더 이름을 제공할 수 있습니다. 이 단계는 조직의 요구 사항을 충족하기 위한 것이지만 필수 사항은 아닙니다.
+
image:evs-create-rp-wiz-c-compute-resources-1-4.png["복제 계획, 컴퓨팅 리소스 생성"]





[[map-virtual-network-resources]]
=== 가상 네트워크 리소스 매핑

각 VM은 vCenter 네트워크 인프라 내의 가상 네트워크에 연결된 하나 이상의 가상 NIC를 가질 수 있습니다. 재해 복구 사이트에서 재시작될 때 각 VM이 원하는 네트워크에 올바르게 연결되도록 하려면, 이러한 VM을 연결할 재해 복구 사이트의 가상 네트워크를 식별하십시오. 이를 위해 온프레미스 사이트의 각 가상 네트워크를 재해 복구 사이트의 관련 네트워크에 매핑합니다.

. 드롭다운 목록에서 대상 세그먼트를 선택합니다.
. 나열된 각 소스 가상 네트워크에 대해 이전 단계를 반복합니다.
+
image:evs-create-rp-wiz-c-network-resources-1-2.png["복제 계획, 네트워크 리소스 생성"]





[[define-options-for-vm-reconfiguration-during-failover]]
=== 장애 조치 중 VM 재구성에 대한 옵션 정의

각 VM은 DR vCenter 사이트에서 올바르게 작동하려면 수정이 필요할 수 있습니다.  가상 머신 섹션에서는 필요한 변경 사항을 제공할 수 있습니다.

기본적으로 Disaster Recovery는 소스 온프레미스 사이트에서 사용되는 것과 동일한 설정을 각 VM에 사용합니다. 이는 VM이 동일한 IP 주소, 가상 CPU 및 가상 DRAM 구성을 사용한다고 가정합니다.



[[network-reconfiguration]]
=== 네트워크 재구성

지원되는 IP 주소 유형은 정적 및 DHCP입니다.  고정 IP 주소의 경우 다음과 같은 대상 IP 설정이 있습니다.

* *소스와 동일*: 이름에서 알 수 있듯이, 이 서비스는 소스 사이트의 VM에서 사용된 것과 동일한 IP 주소를 대상 VM에서 사용합니다.  이렇게 하려면 이전 단계에서 매핑된 가상 네트워크를 동일한 서브넷 설정으로 구성해야 합니다.
* *소스와 다름*: 서비스는 이전 섹션에서 매핑한 대상 가상 네트워크에서 사용되는 적절한 서브넷에 대해 구성해야 하는 각 VM에 대한 IP 주소 필드 세트를 제공합니다.  각 VM에 대해 IP 주소, 서브넷 마스크, DNS 및 기본 게이트웨이 값을 제공해야 합니다.  선택적으로 모든 VM에 대해 동일한 서브넷 마스크, DNS 및 게이트웨이 설정을 사용하면 모든 VM이 동일한 서브넷에 연결되는 경우 프로세스가 간소화됩니다.
* *서브넷 매핑*: 이 옵션은 대상 가상 네트워크의 CIDR 구성에 따라 각 VM의 IP 주소를 재구성합니다.  이 기능을 사용하려면 사이트 페이지의 vCenter 정보에서 변경한 대로 각 vCenter의 가상 네트워크에 서비스 내에서 정의된 CIDR 설정이 있는지 확인하세요.


서브넷을 구성한 후, 서브넷 매핑은 소스 및 대상 VM 구성 모두에 IP 주소의 동일한 호스트 부분을 사용하지만, 제공된 CIDR 정보를 기반으로 IP 주소의 서브넷 구성 요소를 대체합니다. 또한 이 기능을 사용하려면 소스 및 대상 가상 네트워크의 IP 주소 클래스(CIDR의  `/xx` 구성 요소)가 동일해야 합니다. 이렇게 하면 대상 사이트에 보호된 VM을 모두 호스팅할 수 있는 충분한 IP 주소가 확보됩니다.

이 Amazon EVS 설정에서는 소스 및 대상 IP 구성이 동일하며 추가적인 재구성이 필요하지 않다고 가정합니다.

.네트워크 설정 재구성 변경
. 장애 조치된 VM에 사용할 IP 주소 유형을 선택합니다.
. 선택적으로, 선택적 접두사 및 접미사 값을 제공하여 재시작된 VM에 대한 VM 이름 변경 체계를 제공할 수 있습니다.
+
image:evs-create-rp-wiz-c-vm-resources-network-1-2.png["복제 계획, 네트워크 리소스 생성"]





[[vm-compute-resource-reconfiguration]]
=== VM 컴퓨팅 리소스 재구성

가상 머신 컴퓨팅 리소스를 재구성하는 데에는 여러 가지 옵션이 있습니다. Disaster Recovery는 가상 CPU 개수, 가상 DRAM 용량 및 VM 이름 변경을 지원합니다.


NOTE: 다음 단계는 선택 사항입니다.

.VM 구성 변경
. 선택적으로 각 VM이 사용할 가상 CPU 수를 수정할 수 있습니다. 재해 복구 vCenter 클러스터 호스트의 CPU 코어 수가 원본 vCenter 클러스터보다 적은 경우 이 기능이 필요할 수 있습니다.
. 선택적으로 각 VM이 사용할 가상 DRAM 용량을 수정할 수 있습니다. 재해 복구 vCenter 클러스터 호스트의 물리적 DRAM 용량이 원본 vCenter 클러스터 호스트보다 부족한 경우에 필요할 수 있습니다.
+
image:evs-create-rp-wiz-c-vm-resources-cpu-mem-1-2.png["복제 계획, VM 리소스 생성"]





[[boot-order]]
=== 부팅 순서

NetApp Disaster Recovery는 부팅 순서 필드를 기반으로 VM을 순차적으로 재시작하는 기능을 지원합니다. 부팅 순서 필드는 각 리소스 그룹의 VM이 시작되는 순서를 나타냅니다. 부팅 순서 필드에 동일한 값을 가진 VM은 병렬로 부팅됩니다.


NOTE: 부팅 순서 설정은 선택 사항입니다

.부팅 순서 설정 수정
. 선택적으로 VM이 재시작되는 순서를 수정합니다. 이 필드에는 임의의 숫자 값을 입력할 수 있습니다. Disaster Recovery는 동일한 숫자 값을 가진 VM을 병렬로 재시작하려고 시도합니다.
. 선택적으로 각 VM 재시작 사이에 사용할 지연 시간을 지정할 수 있습니다. 이 시간은 해당 VM의 재시작이 완료된 후, 부팅 순서 번호가 다음으로 높은 VM이 재시작되기 전에 적용됩니다. 이 값은 분 단위입니다.
+
image:evs-create-rp-wiz-c-vm-resources-boot-delay-1-2.png["복제 계획, 부팅 순서 생성"]





[[custom-guest-os-operations]]
=== 사용자 정의 게스트 OS 작업

재해 복구는 각 VM에 대해 일부 게스트 OS 작업 수행을 지원합니다.

* Disaster Recovery는 Oracle 데이터베이스 및 Microsoft SQL Server 데이터베이스를 실행하는 VM에 대해 애플리케이션 정합성 보장 백업을 생성할 수 있습니다.
* Disaster Recovery는 각 VM의 게스트 OS에 대한 사용자 지정 스크립트를 실행할 수 있습니다. 이러한 스크립트를 실행하려면 게스트 OS에서 허용하는 사용자 자격 증명과 스크립트에 나열된 작업을 실행할 수 있는 충분한 권한이 필요합니다.


.각 VM의 사용자 정의 게스트 OS 작업 수정
. 선택적으로, VM에서 Oracle 또는 SQL Server 데이터베이스를 호스팅하는 경우 *애플리케이션 정합성 보장 복제본 생성* 확인란을 선택할 수 있습니다.
. 선택적으로, 시작 프로세스의 일부로 게스트 OS 내에서 사용자 지정 작업을 수행하려면 모든 VM에 대한 스크립트를 업로드하십시오. 모든 VM에서 단일 스크립트를 실행하려면 강조 표시된 확인란을 선택하고 필드를 작성하십시오.
. 특정 구성을 변경하려면 작업을 수행할 수 있는 적절한 권한이 있는 사용자 자격 증명이 필요합니다.  다음의 경우 자격 증명을 제공하세요.
+
** 스크립트는 게스트 OS에 의해 VM 내에서 실행됩니다.

[[map-datastores]]
=== 지도 데이터 저장소

복제 계획을 수립하는 마지막 단계는 ONTAP이 데이터스토어를 보호하는 방법을 결정하는 것입니다. 이러한 설정은 복제 계획의 복구 시점 목표(RPO), 유지 관리할 백업 개수, 그리고 각 vCenter 데이터스토어를 호스팅하는 ONTAP 볼륨을 복제할 위치를 정의합니다.

기본적으로 Disaster Recovery는 자체 스냅샷 복제 일정을 관리합니다. 하지만 선택적으로 기존 SnapMirror 복제 정책 일정을 데이터 저장소 보호에 사용하도록 지정할 수 있습니다.

또한 선택적으로 사용할 데이터 논리 인터페이스(LIF) 및 엑스포트 정책을 사용자 지정할 수 있습니다. 이러한 설정을 제공하지 않으면 Disaster Recovery는 해당 프로토콜(NFS, iSCSI 또는 FC)과 연결된 모든 데이터 논리 인터페이스(LIF)를 사용하고 NFS 볼륨에 대해서는 기본 엑스포트 정책을 사용합니다.

.데이터 저장소(볼륨) 매핑 구성
. 선택적으로, 기존 ONTAP SnapMirror 복제 일정을 사용할지 또는 Disaster Recovery를 통해 VM을 보호할지(기본값) 결정할 수 있습니다.
. 서비스가 백업을 시작해야 하는 시작점을 제공합니다.
. 서비스가 백업을 수행하고 이를 DR 대상 Amazon FSx for NetApp ONTAP 클러스터에 복제해야 하는 빈도를 지정합니다.
. 얼마나 많은 과거 백업을 보관해야 하는지 지정합니다.  이 서비스는 소스 및 대상 스토리지 클러스터에서 동일한 수의 백업을 유지 관리합니다.
. 선택적으로 각 볼륨에 대한 기본 논리 인터페이스(데이터 LIF)를 선택할 수 있습니다. 아무것도 선택하지 않으면 볼륨 액세스 프로토콜을 지원하는 대상 SVM의 모든 데이터 LIF가 구성됩니다.
. 선택적으로 NFS 볼륨에 대한 내보내기 정책을 선택할 수 있습니다. 선택하지 않으면 기본 내보내기 정책이 사용됩니다.
+
