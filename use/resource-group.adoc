= NetApp Disaster Recovery에서 리소스 그룹을 생성합니다.
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/use/


[role="lead"]
사이트에 리소스를 추가한 후에는 리소스 그룹을 생성하여 VM, 데이터스토어 또는 Kubernetes 클러스터를 단일 단위로 구성할 수 있습니다. 리소스 그룹을 사용하면 종속 리소스를 요구 사항에 맞는 논리적 그룹으로 구성할 수 있습니다. 예를 들어, 특정 애플리케이션에 사용되는 VM을 그룹화하거나 유사한 계층을 공유하는 애플리케이션을 그룹화할 수 있습니다. 또한 리소스 그룹에는 복구 중에 실행되는 지연 부팅 순서를 포함하여 리소스가 올바른 순서로 시작되도록 할 수 있습니다.

*필요한 NetApp Console 역할* 이 작업을 수행하려면 Super admin, Disaster recovery admin 또는 Disaster recovery application admin 역할이 필요합니다. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-disaster-rec-roles.html["NetApp Disaster Recovery 의 사용자 역할 및 권한에 대해 알아보세요."^]. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["모든 서비스에 대한 NetApp Console 액세스 역할에 대해 알아보세요."^].

*이 작업에 관하여*

VM 자체를 그룹화하거나 데이터 저장소의 VM을 그룹화할 수 있습니다.

다음 방법을 사용하여 리소스 그룹을 만들 수 있습니다.

* 리소스 그룹 옵션에서
* 재해 복구 또는 복제 계획을 생성하는 동안 소스 vCenter 클러스터에서 호스팅되는 VM이 많은 경우 복제 계획을 생성하는 동안 리소스 그룹을 생성하는 것이 더 쉬울 수 있습니다. 복제 계획을 생성하는 동안 리소스 그룹을 생성하는 방법에 대한 지침은 link:task-replication-plan-vmware.html["복제 계획 만들기"]을 참조하십시오.



TIP: 각 리소스 그룹에는 하나 이상의 VM, 데이터스토어 또는 Kubernetes 클러스터가 포함될 수 있습니다. VM은 복제 계획에 포함된 순서에 따라 켜집니다. 리소스 그룹 목록에서 VM 또는 데이터스토어를 위아래로 드래그하여 순서를 변경할 수 있습니다.



[[about-resource-groups]]
== 리소스 그룹에 관하여

리소스 그룹을 사용하면 VM, 데이터 저장소 또는 Kubernetes 애플리케이션을 단일 단위로 결합할 수 있습니다.

예를 들어, 판매 시점 관리 애플리케이션은 데이터베이스, 비즈니스 로직, 매장을 위해 여러 개의 VM을 사용할 수 있습니다.  이러한 모든 VM을 하나의 리소스 그룹으로 관리할 수 있습니다.  애플리케이션에 필요한 모든 VM의 VM 시작 순서, 네트워크 연결 및 복구에 대한 복제 계획 규칙을 적용하기 위해 리소스 그룹을 설정합니다.



[[how-resource-groups-work]]
=== 리소스 그룹 작동 방식

재해 복구는 리소스 그룹 내 VM을 호스팅하는 기본 ONTAP 볼륨 및 LUN을 복제하여 VM을 보호합니다. 이를 위해 시스템은 vCenter에 리소스 그룹 내 VM을 호스팅하는 각 데이터스토어의 이름을 쿼리합니다. 그러면 재해 복구는 해당 데이터스토어를 호스팅하는 소스 ONTAP 볼륨 또는 LUN을 식별합니다. 모든 보호는 SnapMirror 복제를 사용하여 ONTAP 볼륨 수준에서 수행됩니다.

리소스 그룹의 VM이 서로 다른 데이터스토어에 호스팅되는 경우 재해 복구는 다음 방법 중 하나를 사용하여 ONTAP 볼륨 또는 LUN의 데이터 일관성 스냅샷을 생성합니다.

[cols="30,65a"]
|===
| FlexVol 볼륨의 상대적 위치 | 스냅샷 복제 프로세스 


| 여러 데이터 저장소 - *동일한 SVM*의 FlexVol 볼륨  a| 
* ONTAP 일관성 그룹이 생성되었습니다.
* 일관성 그룹의 스냅샷이 촬영되었습니다.
* 볼륨 범위 SnapMirror 복제가 수행되었습니다.




| 여러 데이터 저장소 - *여러 SVM*의 FlexVol 볼륨  a| 
* ONTAP API: `cg_start`. 모든 볼륨을 정지시켜 스냅샷을 생성할 수 있도록 하고, 모든 리소스 그룹 볼륨에 대해 볼륨 범위의 스냅샷 생성을 시작합니다.
* ONTAP API: `cg_end` .  모든 볼륨에서 I/O를 재개하고 스냅샷이 촬영된 후 볼륨 범위 SnapMirror 복제를 활성화합니다.


|===


[[best-practices-for-resource-groups]]
== 리소스 그룹을 위한 모범 사례

리소스 그룹을 생성할 때 다음 시나리오를 고려하십시오:

* 리소스 그룹에 데이터 저장소 또는 네임스페이스를 추가하기 전에 수동 탐색을 시작하거나 예약된 탐색이 실행될 때까지 기다리십시오. 이렇게 하면 VM이 탐색되어 리소스 그룹에 표시됩니다. 수동 탐색을 시작하지 않으면 리소스가 리소스 그룹에 표시되지 않을 수 있습니다.
* 데이터스토어에 하나 이상의 리소스(VM 또는 네임스페이스)가 있는지 확인하십시오. 데이터스토어에 리소스가 없으면 Disaster Recovery가 데이터스토어를 탐색하지 않습니다.
* 단일 데이터 저장소는 두 개 이상의 복제 계획으로 보호되는 VM을 호스팅해서는 안 됩니다.
* 보호된 리소스와 보호되지 않은 리소스를 동일한 데이터스토어에 호스팅하지 마십시오. 보호된 리소스와 보호되지 않은 리소스를 동일한 데이터스토어에 호스팅하면 다음과 같은 문제가 발생할 수 있습니다.
+
** 재해 복구는 SnapMirror를 사용하고 시스템이 전체 ONTAP 볼륨을 복제하기 때문에 해당 볼륨의 사용 용량이 라이선스 계산에 사용됩니다. 이 경우 보호되는 VM과 보호되지 않는 VM 모두에서 사용되는 볼륨 공간이 이 계산에 포함됩니다.
** 리소스 그룹 및 관련 엔티티를 재해 복구 사이트로 페일오버해야 하는 경우, 보호되지 않은 리소스(리소스 그룹에 속하지 않지만 ONTAP 볼륨에 호스팅된 VM 또는 네임스페이스)는 페일오버 프로세스로 인해 소스 사이트에 더 이상 존재하지 않게 되어 소스 사이트에서 보호되지 않은 VM이 실패하게 됩니다. 또한 Disaster Recovery는 페일오버 사이트에서 이러한 보호되지 않은 리소스를 시작하지 않습니다.


* 리소스를 보호하려면 해당 리소스를 리소스 그룹에 포함시켜야 합니다.


*모범 사례*: NetApp Disaster Recovery를 배포하기 전에 VM을 구성하여 데이터스토어 확산을 최소화하십시오. 보호가 필요한 VM은 데이터스토어의 일부에 배치하고, 보호되지 않을 VM은 다른 데이터스토어에 배치하십시오. 특정 데이터스토어에 있는 VM이 서로 다른 복제 계획의 보호를 받지 않도록 하십시오.

====
.vCenters
--
.단계
. Disaster Recovery에서 사이드바의 **리소스 그룹**을 선택합니다.
. 드롭다운 메뉴에서 *VMware*로 필터링합니다.
+
image::site-type-toggle.png[사이트 유형 전환 스크린샷]

. NetApp Disaster Recovery 메뉴에서 *리소스 그룹*을 선택합니다.
. *추가*를 선택하세요.
. 리소스 그룹의 이름을 입력하세요.
. VM이 있는 소스 vCenter 클러스터를 선택합니다.
. 검색 방법에 따라 *가상 머신* 또는 *데이터 저장소*를 선택하세요.
. *리소스 그룹 추가* 탭을 선택합니다.  시스템은 선택된 vCenter 클러스터에 있는 모든 데이터 저장소 또는 VM을 나열합니다.  *데이터 저장소*를 선택한 경우 시스템은 선택한 vCenter 클러스터의 모든 데이터 저장소를 나열합니다.  *가상 머신*을 선택한 경우 시스템은 선택한 vCenter 클러스터에 있는 모든 VM을 나열합니다.
. 리소스 그룹 추가 페이지의 왼쪽에서 보호하려는 VM을 선택합니다.
+
image:dr-resource-groups-add.png["리소스 그룹 추가 페이지를 보여주는 스크린샷"]

+
image:dr-resource-groups-datastores-add.png["리소스 그룹 추가 페이지를 보여주는 스크린샷"]

. 원하는 경우 목록에서 각 VM을 위나 아래로 끌어서 오른쪽에 있는 VM의 순서를 변경합니다.  VM은 포함된 순서에 따라 전원이 켜집니다.
. *추가*를 선택하세요.


--
.Kubernetes
--
.단계
. Disaster Recovery에서 사이드바의 **리소스 그룹**을 선택합니다.
. 드롭다운 메뉴에서 *Kubernetes*로 필터링합니다.
+
image::site-type-toggle.png[사이트 유형 전환 스크린샷]

. *추가*를 선택하세요.
. 리소스 그룹의 **이름**을 입력하고 드롭다운 메뉴에서 Kubernetes **클러스터**를 선택합니다.
. 리소스 그룹에 추가할 *네임스페이스*를 선택합니다.
. 리소스 유형을 분류합니다. 기본값은 "모두 포함"으로, 여러 리소스 유형을 나타냅니다.
. 선택적으로 *Label selectors*를 포함할 수 있습니다.
+
image:kubernetes-resource-group.png["Kubernetes 리소스 그룹 추가 스크린샷"]

. 선택적으로 *+ Cluster-scoped resources*를 선택하여 네임스페이스에 속하지 않는 리소스를 추가할 수 있습니다. 이 옵션을 선택하면 *Group*, *Version*, *Kind*를 선택하고 필요에 따라 레이블 선택기를 추가합니다. **Add resource**를 선택합니다.
+
image:kubernetes-cluster-scoped.png["클러스터 범위 Kubernetes 리소스 추가 스크린샷"]

. **추가**를 선택합니다.
